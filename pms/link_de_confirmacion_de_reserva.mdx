## Qué es

El **link de confirmación de reserva** abre una página pública, en la web del hotel, donde el huésped ve **el estado actual de su reserva**: quién es el titular, las fechas, cada habitación con sus huéspedes y camas, el detalle de los importes, lo que ya pagó, lo que le falta pagar y la política de cancelación.

La clave es que es un **resumen vivo**: no es una foto del momento en que se hizo la reserva. Cada vez que el huésped abre el link, la página le pide los datos al sistema **en ese momento**. Si en el PMS cambiaste una habitación, agregaste un huésped, cargaste un consumo o registraste un pago, el huésped lo ve la próxima vez que abra o recargue la página.

<Note>
  **💡 En una frase**
  
  El presupuesto dice **lo que el huésped compró**. La confirmación dice **lo que hay hoy en su reserva**.
</Note>

La página toma el **color, el logo y los datos de contacto** de tu establecimiento, así que el huésped la reconoce como tuya. Se ve bien en el celular y se puede imprimir.

---

## Confirmación vs. presupuesto original

Hay dos páginas distintas que el huésped puede recibir. Conviene no confundirlas:

| Tema                      | Presupuesto original                     | Confirmación de reserva                                                  |
| ------------------------- | ---------------------------------------- | ------------------------------------------------------------------------ |
| **Qué muestra**           | Lo que se cotizó y compró, tal cual      | El estado actual de la reserva **VIVO**                                  |
| **Cambia si editás la reserva** | No                                       | Sí, al recargar                                                          |
| **Habitaciones y huéspedes** | Las categorías cotizadas                 | Cada habitación asignada, con sus huéspedes y camas                      |
| **Consumos y pagos**      | —                                        | Sí, con saldo pendiente                                                  |
| **Sirve para una consulta** | Sí, si tiene presupuesto                 | No, solo para reservas                                                   |
| **Cómo se llega**         | "Copiar link presupuesto original"       | "Copiar link confirmación de reserva"                                    |

Desde la confirmación el huésped puede abrir el presupuesto con el botón **"Ver presupuesto original"** (ver sección 17), así que con mandar la confirmación alcanza.

En las **plantillas de correo** podés insertar la variable **`[var_confirmation_v2]`**. Al enviar el mail, el sistema la reemplaza por el link de confirmación de esa reserva, con su token. Es la forma recomendada de incluirlo en el correo de confirmación, en el recordatorio pre-llegada o en el de bienvenida.

## El token: la llave del link

El número de reserva es fácil de adivinar: son correlativos. Si alcanzara con cambiar `CID=11845210` por `CID=11845211` para ver otra reserva, cualquiera podría ver nombres, correos, teléfonos e importes de otros huéspedes. **El token es lo que lo impide.**

<CardGroup cols={3}>
  <Card title="✅ CID + token correcto" icon="check-circle">
    La página muestra la reserva.
    text
    ?CID=11845210&token=4f9c…a2d4
    
  </Card>
  <Card title="⛔ Otro CID, mismo token" icon="x-circle">
    "El enlace no es válido". El token es de **una sola** reserva.
    text
    ?CID=11845211&token=4f9c…a2d4
    
  </Card>
  <Card title="⛔ Sin token o token cortado" icon="x-circle">
    "El enlace no es válido". Tiene que coincidir carácter por carácter.
    text
    ?CID=11845210
    
  </Card>
</CardGroup>

### Cómo es el token

-   **Es aleatorio y largo**: 64 caracteres hexadecimales (32 bytes al azar). No se puede adivinar ni deducir del número de reserva.
-   **Es único por reserva** y **no cambia**: el link que mandaste hoy sigue siendo el mismo mañana, aunque edites la reserva.
-   **Se compara exacto**, letra por letra. Si al pegarlo se perdió un carácter (pasa en algunos chats que cortan links largos), el link deja de funcionar.

### Cuándo se crea

No tenés que hacer nada: el token se genera solo.

| Cómo entró la reserva                                              | Cuándo recibe su token                                        |
| ------------------------------------------------------------------ | ------------------------------------------------------------- |
| Motor de reservas (compra online)                                  | En el momento de la compra                                    |
| Cargada en el PMS (mostrador, consulta, presupuestar, inbox, tickets) | Al crearla                                                    |
| Reserva vieja que todavía no tenía                                 | La primera vez que alguien pide el link para compartirlo      |

<Warning>
  **Tratalo como una contraseña**
  
  Quien tenga el link completo ve la reserva. Mandalo **solo al titular** (o a quien él indique), no lo publiques y no lo pegues en canales abiertos. **Nunca armes el link a mano** cambiando el número: usá siempre "Copiar link" o la variable del correo.
</Warning>

## Quién puede abrirlo y hasta cuándo

Tener el token no alcanza: además, la reserva tiene que estar en un estado donde tenga sentido confirmarla. Cada vez que alguien abre el link, el sistema revisa **cuatro cosas, en este orden**:

<Steps>
    <Step title="¿La reserva existe?">
        Un número inexistente o una reserva eliminada no se muestran.
    </Step>
    <Step title="¿Es una reserva activa?">
        Solo se muestran reservas en **preventa, venta, postventa, check-in, in-house o check-out**. Una **consulta** nunca: la página afirma que hay una reserva y una consulta todavía no lo es. Una reserva **cancelada o caída** tampoco.
    </Step>
    <Step title="¿Sigue vigente?">
        El link funciona hasta **7 días después de la fecha de salida**. Después vence solo.
    </Step>
    <Step title="¿El token coincide?">
        Si la reserva tiene token, el del link tiene que ser exactamente ese.
    </Step>
</Steps>

### La vida del link, en una línea de tiempo

El link es válido desde que la reserva se confirma hasta 7 días después del check-out. Si la reserva se cancela, el link deja de funcionar inmediatamente.

-   **Consulta:** No abre.
-   **Reserva confirmada → Estadía:** Abre y se actualiza con cada cambio.
-   **Hasta 7 días post-check-out:** Sigue abriendo.
-   **Vencido (más de 7 días post-check-out):** No abre.

<Info>
Si la reserva se cancela, el link deja de abrir en ese mismo momento, esté donde esté en la línea de tiempo.
</Info>

<Note>
  **Reservas antiguas sin token**
  
  Algunas reservas anteriores al token nunca recibieron uno. Para no romper los links que esos huéspedes ya tienen, **esas reservas siguen abriendo con el número solo**, siempre que cumplan los puntos 1 a 3. En cuanto alguien pide el link para compartir, la reserva recibe su token y desde ahí queda protegida como cualquier otra.
</Note>

## "El enlace no es válido"

Si alguna de las cuatro revisiones falla, el huésped ve esta pantalla:

<Card title="⚠ El enlace no es válido">
  El enlace de tu confirmación de reserva no es válido o ya expiró. Por favor, comunícate con el establecimiento para más información.
</Card>

<Info>Se muestra un único mensaje, neutro, para todos los casos.</Info>

**¿Por qué no dice el motivo?** A propósito. Si la página dijera "esta reserva está cancelada" o "esta reserva venció", cualquiera podría ir probando números y averiguar qué reservas existen y en qué estado están. Con un mensaje único, quien no tiene el link correcto no aprende nada.

Por eso el mensaje invita al huésped a **comunicarse con el establecimiento**: vos sí podés ver el motivo en el PMS.

| Lo que ves en el PMS                       | Por qué no abre                             | Qué hacer                                                               |
| ------------------------------------------ | ------------------------------------------- | ----------------------------------------------------------------------- |
| La reserva está cancelada / caída          | No hay nada que confirmar                   | Es correcto que no abra                                                 |
| Todavía es una consulta                    | Aún no es reserva                           | Mandá el presupuesto; cuando se confirme, la confirmación              |
| El check-out fue hace más de 7 días        | El link venció                              | Si el huésped necesita el detalle, enviáselo desde el PMS               |
| La reserva está bien                       | El link llegó incompleto o fue modificado   | Volvé a copiarlo con "Copiar link confirmación de reserva" y reenviálo  |

-   **Imprimir** — abre la impresión del navegador.

Debajo de la cabecera va el título con el número de reserva y una etiqueta con el estado del pago:

## Titular

Nombre y apellido del titular, su **email** y su **teléfono**, tal como están cargados en la reserva. Si alguno está vacío, no aparece.

Si el huésped te avisa que un dato está mal, corregilo en la reserva: la próxima vez que abra el link ya lo ve bien.

## Estadía

<Frame caption="Resumen de la estadía completa, incluyendo fechas, noches, huéspedes y régimen.">
    <img src="https://mintlify.s3-us-west-1.amazonaws.com/pxsol/docs/confirmation-link-v2/stay.png" alt="Bloque de información de la estadía." />
</Frame>

<Info>El resumen de toda la reserva. El detalle por habitación está en el bloque siguiente.</Info>

-   **Llegada / Salida** — las fechas de la reserva completa. Las fechas se escriben con el mes en letras ("12 oct 2026") para que no haya confusión entre día y mes en ningún país.
-   **Noches** — ojo con este dato, ver el recuadro de abajo.
-   **Llegada anticipada / Salida tardía** — **Sí** en verde o **No** en rojo, a nivel reserva. Cada habitación tiene además los suyos.
-   **Huéspedes** — adultos, niños y bebés, contados **habitación por habitación** a partir de cómo está armada la reserva hoy.
-   **Régimen** — el plan de comidas de la reserva, si tiene.

<Warning>
  **🛏 "Noches" son noches-habitación**

  En el bloque Estadía, **Noches** suma las noches de **todas** las habitaciones. En el ejemplo son 2 habitaciones × 2 noches = **4**, aunque del 12 al 14 de octubre haya 2 noches de calendario.

  Es intencional: dividir el total por ese número da el **precio promedio por noche** que se ve en el resumen económico, y ese promedio coincide con las tarifas de cada habitación. El largo de la estadía lo dicen Llegada y Salida; las noches de cada habitación, su propio bloque.
</Warning>

## Habitaciones

Una tarjeta por cada habitación de la reserva, con todo lo que el huésped necesita saber de ella:

<Frame caption="Detalle de cada habitación. La habitación 204 tiene salida tardía, cuyo precio se detalla por separado.">
    <img src="https://mintlify.s3-us-west-1.amazonaws.com/pxsol/docs/confirmation-link-v2/rooms.png" alt="Detalle de las habitaciones asignadas en la reserva." />
</Frame>

| Dato                                  | Qué muestra                                                                                                                             |
| ------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------- |
| **Habitación**                        | El nombre o número de la habitación asignada.                                                                                           |
| **Categoría**                         | La categoría con la que se vendió. Si hiciste un upgrade, acá sigue diciendo lo que el huésped compró.                                    |
| **Huéspedes**                         | Cuántas personas hay cargadas en esa habitación (adultos + niños + bebés).                                                              |
| **Ingreso / Salida**                  | Las fechas de **esa** habitación. Pueden diferir de las de la reserva si una habitación entra o sale otro día. Si una misma habitación aparece dos veces (estadía partida), cada tarjeta tiene sus fechas. |
| **Llegada anticipada / Salida tardía**| Sí o No para esa habitación.                                                                                                            |
| **Distribución de camas**             | Íconos con cantidad: cama grande, cama chica y cuna (al pasar el mouse dice cuál es). Un guion si no hay camas configuradas.              |
| **Régimen**                           | El de la habitación; si no tiene uno propio, el de la reserva.                                                                          |
| **Noches**                            | Las noches de esa habitación.                                                                                                           |
| **Precio por noche**                  | El promedio de las noches de alojamiento de esa habitación. **No** incluye llegada anticipada ni salida tardía, porque no son noches.    |
| **Precio llegada anticipada / salida tardía** | Solo si se cobraron. Van como línea propia para que el total se entienda solo.                                                          |
| **Total**                             | Todo el alojamiento de esa habitación: noches + llegada anticipada + salida tardía.                                                     |

Los precios y el total aparecen solo si son mayores a cero. Si la reserva no tiene habitaciones asignadas una por una (por ejemplo, porque el hotel no las gestiona), el bloque muestra solo la cantidad: **"2 habitaciones"**.

## Resumen económico

<Frame caption="Resumen económico con desglose de alojamiento, consumos, total, pagado y saldo. El precio promedio por noche es de 463.000 ÷ 4 = 115.750.">
    <img src="https://mintlify.s3-us-west-1.amazonaws.com/pxsol/docs/confirmation-link-v2/summary.png" alt="Bloque de resumen económico de la reserva." />
</Frame>

**Las líneas de desglose** (en gris) aparecen solo si tienen un importe distinto de cero:

-   **Alojamiento** — noches de todas las habitaciones, incluyendo llegadas anticipadas y salidas tardías.
-   **Consumos y extras** — todo lo que no es alojamiento: frigobar, estacionamiento, servicios, etc.
-   **Impuestos** — los impuestos de la reserva, cuando se discriminan.
-   **Tributos de comprobantes** — impuestos que surgen de las facturas emitidas.
-   **Devoluciones** — se muestran con signo menos.

**Las líneas finales** están siempre:

-   **Total** — lo que cuesta la reserva hoy.
-   **Pagado** — la suma de los pagos registrados.
-   **Saldo pendiente** — Total − Pagado. En **ámbar** si falta pagar; en **verde** y en cero cuando ya está todo pago. Nunca se muestra negativo.

Además:

-   **Precio promedio por noche** — el total dividido por las noches-habitación.
-   **Promociones aplicadas** — las promociones que se aplicaron a la reserva, como etiquetas verdes.

Los importes se muestran en la **moneda de la reserva** y con los **decimales configurados** en tu punto de venta. El formato de los números sigue el idioma: `463.000,00` en español y portugués, `463,000.00` en inglés.

Si cargaste consumos en los folios de la reserva, el huésped los ve uno por uno:

<Frame caption="Tabla de consumos y extras cargados a la reserva. 'General' indica un consumo no asociado a una habitación específica.">
    <img src="https://mintlify.s3-us-west-1.amazonaws.com/pxsol/docs/confirmation-link-v2/charges.png" alt="Lista de consumos y extras." />

-   Cada consumo se muestra en la moneda de su folio.

## Pagos registrados

<Frame>
    <img src="https://mintlify.s3-us-west-1.amazonaws.com/pxsol/docs/confirmation-link-v2/payments.png" alt="Tabla de pagos registrados en la reserva." />

-   Siempre se muestra también la dirección escrita, por si el botón no abre o el celular no puede escanear.
-   Este bloque **no se imprime**.

## Siempre actualizada

Esta es la diferencia más importante con las confirmaciones de antes. La página **no guarda una copia**: cada vez que se abre, lee la reserva **como está en ese momento**.

<CardGroup cols={2}>
    <Card title="Lunes · en el PMS">
        Pasás la reserva de la hab. **101** a la **305**, agregás un niño y registrás la seña.
    </Card>
    <Card title="Lunes · el huésped recarga" icon="check-circle">
        Ve la hab. **305**, un huésped más, el pago en "Pagos registrados", el saldo nuevo y "Información actualizada al" con la hora del cambio.
    </Card>
</CardGroup>

Qué se refleja al recargar:

-   Cambios de **habitación**, de **fechas** y de **categoría**.
-   **Huéspedes** agregados o quitados en cada habitación.
-   **Llegada anticipada** y **salida tardía**.
-   **Consumos** cargados o eliminados.
-   **Pagos** registrados y el **saldo**.
-   Datos del **titular**.

<Note>
  **Por qué los huéspedes ahora siempre cuadran**
  
  Antes, la cantidad de huéspedes se tomaba de lo que se cargó al crear la reserva, y no se actualizaba al editar las habitaciones. Pasaba que una reserva de 7 habitaciones con 5 personas cada una mostraba **47 huéspedes** en lugar de **35**. Ahora se cuentan habitación por habitación, a partir de cómo está armada la reserva hoy.
</Note>

**No hace falta volver a mandar el link** después de un cambio: el mismo link muestra lo nuevo. Si querés avisarle al huésped, alcanza con decirle que lo vuelva a abrir.

## Idiomas

La página está en **español, inglés y portugués**: títulos, etiquetas, fechas ("12 oct 2026", "12 Oct 2026", "12 out 2026") y formato de números.

El idioma se elige así, en este orden:

1.  El que diga el link, si termina en `&lng=en`, `&lng=pt` o `&lng=es`.
2.  El **idioma de la reserva**.
3.  El **idioma de tu punto de venta**.
4.  Español, si ninguno de los anteriores es uno de los tres.

Para mandarle el link en otro idioma a un huésped puntual, agregá `&lng=en` (o `&lng=pt`) al final del link copiado. Lo que carga el hotel en texto libre (nombre de la política, descripción de consumos y pagos, régimen) se muestra tal como está cargado.

## Imprimir o guardar en PDF

El botón **Imprimir** de la cabecera abre la impresión del navegador. Desde ahí el huésped puede imprimir en papel o elegir **"Guardar como PDF"**.

La versión impresa está preparada para eso:

-   **Se imprime**: cabecera con logo y datos del hotel, titular, estadía, habitaciones, resumen económico, consumos, pagos, política de cancelación y la fecha de "Información actualizada al".
-   **No se imprime**: los botones (Ir al sitio web, Imprimir, Ver presupuesto), el bloque de pago con link o QR, el pie legal, WhatsApp y el chat.
-   Fondo blanco, sin sombras, y cada tarjeta se mantiene entera en una página cuando es posible.
-   Sin el encabezado y pie automáticos del navegador (fecha, URL): así **el token no queda impreso** en el papel.

## Privacidad: qué nunca muestra

-   **Datos de tarjeta**: nunca. Ni números, ni vencimientos, ni tokens de tarjeta.
-   **Consultas**: nunca. Solo reservas.
-   **Reservas canceladas o vencidas**: no se muestran.
-   **Motivo del rechazo**: no se le dice a quien abre un link inválido.
-   **Buscadores**: la página está marcada para que Google y otros buscadores **no la indexen**.
-   **Estadísticas de conversión**: la confirmación no registra conversiones de Google Analytics ni de publicidad. La conversión ya se registró una vez, al momento de la compra; esta página se abre muchas veces y no debe contarse de nuevo.

## Preguntas frecuentes

<AccordionGroup>
  <Accordion title='No me aparece "Copiar link confirmación de reserva"'>
    El botón solo se ofrece cuando el link va a abrir. Revisá que: la reserva **no sea una consulta** ni esté cancelada; que **tenga presupuesto**; y, si es un **voucher**, que tenga al menos una habitación.
  </Accordion>
  <Accordion title='El huésped dice que el link no abre'>
    Mirá la reserva en el PMS: ¿está cancelada? ¿es todavía una consulta? ¿pasaron más de 7 días desde la salida? Si nada de eso aplica, el link llegó cortado: volvé a copiarlo y reenviálo. Ver la tabla de la sección "El enlace no es válido".
  </Accordion>
  <Accordion title='"Noches" dice 4 pero la estadía es de 2 noches'>
    Es correcto: en el bloque Estadía son noches-habitación (2 habitaciones × 2 noches). Cada habitación muestra sus propias noches. Ver la sección de Estadía.
  </Accordion>
  <Accordion title='El total de una habitación no es noches × precio por noche'>
    Esa habitación tiene llegada anticipada o salida tardía: el total la incluye y su precio aparece en una línea propia justo arriba. El precio por noche es solo el de las noches.
  </Accordion>
  <Accordion title='La categoría dice una cosa y la habitación es de otra'>
    "Categoría" es lo que el huésped compró. Si le diste un upgrade, la habitación asignada puede ser de una categoría superior: es lo esperado.
  </Accordion>
  <Accordion title='No aparecen los consumos'>
    Se listan solo si el establecimiento usa el PMS de Pxsol y los consumos están cargados en los folios de la reserva. Igualmente se suman en "Consumos y extras" del resumen económico.
  </Accordion>
  <Accordion title='No aparece el botón para pagar'>
    El medio de pago de la reserva tiene que ser Link de pago o QR de pago, con la URL configurada, y tiene que quedar saldo. Si la reserva ya está paga, el bloque no se muestra.
  </Accordion>
  <Accordion title='Hice un cambio y el huésped no lo ve'>
    Pedile que recargue la página. Si "Información actualizada al" no muestra la hora de tu cambio, verificá que se haya guardado en la reserva.
  </Accordion>
  <Accordion title='¿Puedo mandar el link sin el token, que es más corto?'>
    No. En cuanto la reserva tiene token, el link sin él no abre. Si el largo molesta, usá un acortador de links sobre el link completo.
  </Accordion>
</AccordionGroup>

## Para soporte: cómo funciona por dentro

Esta sección es para el equipo de soporte y desarrollo.

### El recorrido de una apertura

<Steps>
    <Step title="1. Huésped">
        Abre `gracias_v2.php?CID=…&token=…` en la web del hotel.
    </Step>
    <Step title="2. webroot">
        Llama a api2 con su key interna y pasa el token en el header `X-Reservation-Token`.
    </Step>
    <Step title="3. api2 decide">
        Verifica: Existe → estado visible → dentro de ventana → token coincide. Si falla: 403.
    </Step>
    <Step title="4. Resumen">
        Arma el resumen desde las habitaciones, folios y balance actuales.
    </Step>
    <Step title="5. Render">
        webroot suma datos del POS y del producto (logo, color, legales) y dibuja la página.
    </Step>
</Steps>

-   **Endpoint**: `GET {Api2}/v2/reservations/{CID}/public-summary?context=gracias_v2`, en el grupo de rutas `internalpxsol`. La key `WEBROOT_TO_API2_INTERNAL_KEY` autentica a **webroot**; el `public_access_token` autoriza al **huésped**.
-   El token viaja **por header**, no por query string, para que no quede en los access logs de api2.
-   **Fail-closed**: si webroot no tiene endpoint o key configurados, o api2 responde algo distinto de 200, la página muestra "El enlace no es válido". Nunca se muestra una confirmación a medias.
-   El token se compara con `hash_equals` (byte a byte), no con la collation de MySQL, que es case-insensitive e ignora espacios finales.
-   Se leen **todos** los tokens de `reservation_metadata` de la reserva (la tabla puede tener más de una fila): "tiene token" significa que existe al menos uno, y el del link puede coincidir con cualquiera.

### Motivos de rechazo

La página siempre muestra el mismo mensaje. El motivo real viaja en la respuesta 403 de api2 (`reason`) para diagnóstico interno:

| reason            | Cuándo                                                                      |
| ----------------- | --------------------------------------------------------------------------- |
| `INVALID_CID`     | El CID no es un número positivo.                                            |
| `NOT_FOUND`       | No existe en `mod09_transacciones`, está borrada, o el resumen salió vacío. |
| `CANCELLED`       | Instancia `noventa`, `nvcp`, `90` o `caidas`.                               |
| `NOT_AVAILABLE`   | Cualquier otra instancia fuera de la allowlist (incluida `consulta`).       |
| `EXPIRED`         | `fechaegreso` anterior a hoy − 7 días (reloj de la DB).                     |
| `INVALID_TOKEN`   | La reserva tiene token y el del link falta o no coincide.                   |

<Warning>
Estados visibles (allowlist): `preventa`, `venta`, `postventa`, `checkin`, `inhouse`, `checkout`. Cambiar esta lista o la ventana de 7 días amplía qué reservas son legibles sin sesión: es una decisión de seguridad (CVE-2026-38872) y se discute aparte.
</Warning>

### De dónde sale cada dato

| Bloque                 | Fuente                                                                                                                |
| ---------------------- | --------------------------------------------------------------------------------------------------------------------- |
| Cabecera, titular, estadía, totales | `ReservationService::getReservationSummary()` de api2                                                       |
| Huéspedes              | `reservation_rooms` (no la cabecera `GroupsForm`, que es una foto del alta — NX#152220)                                |
| Detalle por habitación | `reservation_rooms` + folios / `vouchers_items` de alojamiento si la empresa tiene `activate_reservation_rooms`; si no, `neo_ocupacion` |
| Precio por noche       | Promedio de ítems `Accommodation` no borrados, excluyendo ECI/LCO por prefijo de código (NX#154500)                      |
| Consumos               | `vouchers_items` no-alojamiento, solo si `mod00_productos.use_pxsol_pms`                                             |
| Pagos                  | `mod09_balance` con `Status = 1`, importe = créditos − cargos, sin filas en cero                                      |
| Link / QR de pago      | `payment_means` del medio de la reserva (`PaymentLink` / `PaymentQR`)                                                 |
| "Actualizada al"       | `fecha` / `hora` de `mod09_transacciones`                                                                             |
| Logo, nombre, dirección, web | `/product/info` de api1                                                                                             |
| Color, decimales, legales, WhatsApp, favicon | `/pos/info` de api1 (cacheado 30 días en Redis)                                                                   |
